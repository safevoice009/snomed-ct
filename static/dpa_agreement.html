B2B Data Processing Agreement (DPA)

Standard Contractual Clauses under DPDP Act 2023 Section 8(2)

Between SICCE (Data Processor) and Registered Healthcare Entity / Hospital / Clinic (Data Fiduciary)

1. Purpose & Scope of Data Processing

This Data Processing Agreement ("DPA") governs the automated processing of digital clinical text by SICCE on behalf of the Data Fiduciary for ABDM HL7 FHIR R4 interoperability and SNOMED CT / LOINC terminology translation.

2. Obligations of the Data Processor (SICCE)

  • Statutory Instructions: Process personal clinical data strictly in accordance with the documented technical API instructions of the Data Fiduciary.
  • Automated PHI Sanitization: Apply automated pattern masking to direct identifiers prior to cloud model translation.
  • Ephemeral Processing: Retain zero unencrypted raw medical narratives in persistent storage.
  • Breach Notification: In the event of a confirmed security incident, notify the Data Fiduciary without undue delay in accordance with DPDP Act Section 8(6).

3. Obligations of the Data Fiduciary (Hospital / Clinic)

  • Ensure a valid lawful basis and patient consent under ABDM guidelines prior to invoking the API gateway.
  • Maintain sole clinical responsibility for reviewing and verifying all generated FHIR codes before clinical use.

4. Technical & Security Measures

The Data Processor shall maintain industry-standard security safeguards including TLS 1.3 encryption in transit, AES-256 encryption at rest for account tokens, and multi-tenant key isolation.
